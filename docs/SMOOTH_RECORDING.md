# Recording readiness and keyboard panel — 10 September 2026

> Historical context: the Sayso keyboard and its cross-app recording/Live Activity support were removed on 12 September 2026. References and screenshots of those features below describe earlier revisions. See the [README](../README.md) for current behavior.

## Experience

Home opens with the recording action and writing mode. Speech provider, language, downloads, and technical setup remain in Settings. An actual missing-model error links to Sayso’s Settings. The microphone is never opened by passive preparation.

The selected speech backend now lives beyond a successful recording. Opening Sayso prepares installed resources while the person chooses what to do; repeat recordings reuse those resources. Changing provider or replacing/removing a Parakeet installation invalidates the old cache. Memory pressure releases idle resources, defers release until an active recording finishes, and suppresses speculative preparation until a later foreground entry. Idle background cleanup has a 60-second grace period; it is best effort because iOS can suspend the app before its timer runs. iOS may also terminate the process at any time.

Parakeet is batch recognition: microphone capture can begin while any remaining installed-model load runs concurrently, and Stop joins that same task before transcription. Apple’s streaming recognizer needs a ready analyzer before listening; Sayso preloads its shared model resources and gives every recording a fresh result stream and vocabulary context. Passive Apple preparation uses installed assets only. Permission requests and any necessary language installation remain attached to an explicit recording action.

For a writing mode, the app requests Apple Intelligence preparation when recording starts. If a keyboard recording began in Original, selecting a writing mode for Stop also requests preparation while speech finishes. That gives generation lead time without carrying one recording’s conversation into another. The system decides when resources are actually available; this is not a guarantee of zero startup latency.

## Clicking through keyboard dictation

1. Start **Dictate in another app** in Sayso, or use the **Keyboard Dictation** Shortcut, including from an Action button.
2. Return to the destination field and select Sayso from the globe. The extension shows recording mode buttons, **Stop & insert**, and Discard. It contains no letter, number, space, or delete keys; the globe returns to the normal keyboard for typing.
3. Choose Original, Clean, Message, Email, Notes, or a configured custom mode, then tap **Stop & insert**. The selected prompt snapshot is applied by the app and the finished text is inserted at the active cursor.
4. Automatic insertion requires the same visible document, the matching recording UUID and recording provenance, an unexpired pending request, and an unconsumed result. Leaving the keyboard, changing documents, host-app inactivity, or a temporarily unavailable document identifier revokes that pending insertion. The result remains available through an explicit **Insert** button.

Full Access is required for the keyboard to write recording commands. Manually sent results remain readable and explicitly insertable with Full Access off. Stopping in Sayso or through the Live Activity also retains the explicit Insert flow. Discard remains terminal for the session, and a manual re-share never inherits automatic-insertion provenance.

The app snapshots complete writing prompts at recording start and shares only mode IDs, display titles, and icons. It caps this ephemeral catalog at 24 entries, includes the selected saved mode first, and shortens only long display titles. The keyboard never reads surrounding field text or the clipboard. Consumption is claimed before invoking `insertText` to prevent reentrant duplicate insertion; UIKit still offers no transactional delivery acknowledgment across a host crash.

## Platform research

- Apple explicitly provides [prepareToAnalyze(in:)](https://developer.apple.com/documentation/speech/speechanalyzer/preparetoanalyze%28in%3A%29) for early setup, including a nil format when input is not yet known. [Model retention](https://developer.apple.com/documentation/speech/speechanalyzer/options/modelretention-swift.enum/whileinuse) can retain resources until analyzer deallocation. Sayso holds a resource-only analyzer between operations and releases it through the cache lifecycle. [SpeechAnalyzer](https://developer.apple.com/documentation/speech/speechanalyzer) documents reuse of cached resources by different analyzer instances.
- [Foundation Models prewarm](https://developer.apple.com/documentation/foundationmodels/languagemodelsession/prewarm%28promptprefix%3A%29) requests eager loading when generation is likely soon; execution is system-controlled.
- [FluidAudio’s manager](https://github.com/FluidInference/FluidAudio/blob/main/Sources/FluidAudio/ASR/Parakeet/SlidingWindow/TDT/AsrManager.swift) retains loaded models until cleanup. Sayso reuses the manager with a fresh decoder state for each recording and postpones cleanup while an earlier transcription still uses it.
- [Apple’s custom keyboard guide](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html) excludes microphone access. [Review guideline 4.4.1](https://developer.apple.com/app-store/review/guidelines/#extensions) also restricts keyboard app launching. Consequently, this implementation does not offer a misleading cold Record button inside the extension. Initial microphone activation still needs Sayso or its supported foreground Shortcut.
- [documentIdentifier](https://developer.apple.com/documentation/uikit/uitextdocumentproxy/documentidentifier) scopes the insertion request; [text interactions](https://developer.apple.com/documentation/uikit/handling-text-interactions-in-custom-keyboards) provide insertion at the active cursor.
- [Extension-host inactivity notifications](https://developer.apple.com/documentation/foundation/nsnotification/name-swift.struct/nsextensionhostwillresignactive) revoke pending insertion when the destination app loses focus. This is independent of view disappearance because iOS can retain the keyboard view during app switching.
