## Implemented native audio path

[SpeechService.swift](../Sayso/Services/SpeechService.swift) now calls `installAudioTap`, which delivers `AVReadOnlyAudioPCMBuffer` values. These native read-only buffers are Sendable and can outlive the callback. The tap only checks for empty buffers and yields into a bounded stream; overflow ends capture with the existing error. It requests `ceil(sampleRate × 0.1)` frames, corresponding to **100 ms**, within the API's 100–400 ms request range. This is a requested size, not a measured callback-latency guarantee.

One detached consumer creates each mutable `AVAudioPCMBuffer(copying:)`, meters it, and submits it to the converter. The obsolete `CapturedAudio` wrapper is removed. No mutable tap-owned buffer is transferred to another task. Observable level changes still return to the main actor.

[SpeechAudioConverter.swift](../Sayso/Services/SpeechAudioConverter.swift) now wraps `AnalyzerInputConverter(analyzerFormat:configurationHandler:)` with **normal priming**. It rejects analyzer destinations whose common format is not Int16, checks source format, ignores empty inputs, and calls `convert(_:at:)` with `nil` time for contiguous samples. All returned analyzer inputs are consumed. On Stop, queued capture drains, `flush()` outputs are submitted, the analyzer input stream finishes, and finalization follows. The former manual sample-time and padding bookkeeping is removed. Apple's converter may retain its input buffers, which is why the mutable consumer copy remains owned independently of the tap. [Converter documentation](https://developer.apple.com/documentation/speech/analyzerinputconverter), [buffer lifetime and flushing](https://developer.apple.com/documentation/speech/analyzerinputconverter/convert(_:at:)).

The [first executing simulator run](../.build/test-ios27-speech-pipeline-reimported.log) exposed two concrete problems. With `.none` priming, resampling returned 32,011 frames instead of 32,000; an irregular-chunk case also gained eleven frames. Two same-format Float32 cases hit beta 6's fatal precondition requiring signed 16-bit sample data. Production now uses `.normal` priming and throws `incompatibleAudio` for unsupported destinations before entering that native path. Same-format fixtures now use Int16; a separate test confirms that a Float32 destination throws safely. These are observed beta 6 behaviors, not a claim about every possible analyzer format on future releases.

`AnalyzerInputConverter` has no public Sendable conformance. Its wrapper retains the documented exclusive transfer to one consumer task; `@unchecked Sendable` does not permit concurrent converter use. Metadata checks use `AnalyzerInput.bufferDuration` and `bufferFormat`. A narrowly scoped, test-only use of the deprecated `buffer` getter checks actual sample content, with its compiler warning retained. **All ten SpeechPipeline tests now pass**, covering read-only buffer ownership, exact conversion duration and continuous timestamps, irregular stereo chunks, Int16 same-format samples and short tails, resampled tail retention, empty flush, the unsupported-format guard, and transcript revision behavior. These synthetic-buffer checks do not verify real microphone or background capture.

Recording interruption now observes `AVAudioSession.didBecomeInactiveNotification`. Losing the active session ends the recording; a resumption recommendation does not restart the microphone without another user action. Existing session identity checks, Stop/Cancel cleanup, route-loss handling, media-service reset handling, and bounded queues remain in place.

## Implemented model error migration

[IntelligenceService.swift](../Sayso/Services/IntelligenceService.swift) retains the local `SystemLanguageModel`, synchronous `contextSize` and locale support checks, and fresh-session token accounting for instructions, prompt, schema, and response allowance. Prompts, text rules, generation options, and the maximum of one intentional repair are unchanged. Usage telemetry and provider switching were not added.

The legacy `LanguageModelSession.GenerationError` translator is replaced with the current error families:

| iOS 27 error | App behavior |
| --- | --- |
| `LanguageModelError.contextSizeExceeded` | Explain that the input exceeds model capacity. |
| `SystemLanguageModel.Error.assetsUnavailable` | Refresh availability and show the existing model-readiness explanation. |
| `LanguageModelError.unsupportedLanguageOrLocale` | Show the existing unsupported-language explanation. |
| `LanguageModelError.guardrailViolation`, `.refusal` | Preserve Original and report that rewriting could not complete. |
| `LanguageModelError.rateLimited`, `LanguageModelSession.Error.concurrentRequests` | Show the existing busy/retry message. |
| Unsupported guide/capability/transcript content, timeout, session transcript mutation, parsing failures, unknown cases | Use the existing generation-failure fallback while Original remains available. |

Cancellation stays distinct, including a parsing error whose underlying error is `CancellationError`. Rejected parsing content is neither exposed nor retained. Native model errors leave through the outer handler; they do not create another repair loop.

Apple defines legacy-error compatibility by the build toolchain: Xcode 26 builds continue receiving `GenerationError` until rebuilt with Xcode 27. Existing `respond` call sites need no `contextOptions` argument merely to enable the new error types. Production therefore preserves those calls and their schema-inclusion policy. Actual runtime error handling still needs verification. [Error migration](https://developer.apple.com/documentation/foundationmodels/languagemodelsession/generationerror), [current errors](https://developer.apple.com/documentation/foundationmodels/languagemodelerror).

## Deferred alternatives

Audio-file import continues to use `SpeechAnalyzer.analyzeSequence(from: AVAudioFile)`. `AssetInputSequenceProvider` and `CaptureInputSequenceProvider` are not required for this migration. The capture provider would replace the engine/session architecture, and its sequence ends when its audio output is deallocated; stopping capture alone is not documented to finish it. That larger change remains deferred. [Asset provider](https://developer.apple.com/documentation/speech/assetinputsequenceprovider), [capture sequence lifetime](https://developer.apple.com/documentation/speech/captureinputsequenceprovider/analyzerinputs).
