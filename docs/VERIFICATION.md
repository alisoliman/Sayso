## Build 2 recording diagnostics — 8 September

The user reported that recordings returned no detected speech with both internal input and AirPods. They later suspected Mac screen sharing and requested a retry. Neither an application recognition defect nor a screen-sharing cause has been established. Build 2 adds instrumentation and clearer failure messages; it is **not a verified recognition fix**.

[SpeechService](../Sayso/Services/SpeechService.swift) now distinguishes no captured microphone buffers, no converted audio, no analyzed audio and no recognized words. [SpeechDiagnostics](../Sayso/Services/SpeechDiagnostics.swift) keeps aggregate capture/conversion/result counters, normalized level, character counts, selected locale, input port types, numeric formats, stop/outcome and app/OS metadata in memory. Capture counts are observed before conversion; converted counts describe generated input, including converter flushes, rather than proving enqueue or recognition. A zero normalized level is not conclusive evidence of silent hardware input. Reports exclude audio, transcript text, vocabulary, device names, route UIDs and error userInfo. The error alert's **Copy diagnostics** action explicitly writes the report to the local-device pasteboard; there is no automatic upload. DEBUG builds can print the same content-free report locally.
